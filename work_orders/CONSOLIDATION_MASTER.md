### 1.8.5 `.santp` ingestion design — headline findings

- **Corpus is trivially small: 546 files, 2.12 MB total, 3.9 KB average.** Not the 1.75 GB ingest
  it looked like — `Environment.sanpack` is read via the *existing* `Io::SanpackReader::ExtractFiltered`.
- **LuaJIT vendoring reuses from STEP65; its contract does not.** STEP65's `LuaSyntaxCheck_SYS` is
  compile-only and never-execute, defended by a killer test (`while true do end` must return in
  bounded time). A `.santp` is a Lua **assignment statement**, so reading `footprint.x` requires
  *executing* the chunk — `luaL_loadbuffer` alone yields a function and no values. Widening
  `CheckLuaSyntax` would delete the exact property those tests defend. Proposal: a **sibling** SYS
  primitive sharing the library and nothing else, with its own hard sandbox (zero libs, no `ffi`,
  instruction-count hook, size caps, `lua_pcall` only, fresh state per file). **Not covered by
  ARCH §15.8 — needs its own sign-off (Q1).**
- **Five root table names, not two:** `UnitTemplate` (283), `propTemplate` (145), `PropTemplate`
  (4), `ProjectileTemplate` (62), `MarkerTemplate` (6). The last two carry no `footprint` and must
  be skipped **by design, not error-reported**. 12 unit templates put the root assignment below a
  multi-line comment header — a line-anchored or regex reader is wrong from the start.
- **`.sanprop` does not imply Lua.** The 17 `" - Copy".sanprop` files are **JSON**, different
  schema, no `footprint`. A reader must sniff content, never trust the extension.
  `UnitsTemplates.sanpack` is a **22-byte empty zip** — unit templates ship only as loose Lua.
- **Determinism is the real constraint (Q8).** `footprint` is the obvious input for scatter
  spacing and a future ticket will reach for it — silently breaking Constitution §4's
  shared-generation guarantee, since ingested data is not in settings+seed and two users may hold
  different game versions. Recommendation: **ARCH should rule it permanently Visual-class before
  the orchestrator ticket lands.** The failure mode is a divergent competitive map, not a crash.
- **Proposed tickets:** 85 sandboxed Lua eval (SYS) · 86 template source scan (IO) · 87 dialect

## 4. Live-environment findings worth preserving

From the scenario track's live in-game testing — these reversed ratified claims and cost real
debugging time:

- **Cross-tree `Import()` does not work.** A `.lua` in `Sanctuary_Data/Maps/<Map>/` cannot be
  `Import()`ed from `LJ/lua/`. Proven by calling `Engine.FileExists(libPath.."/"..path)` with a
  `../../Sanctuary_Data/...` path: returns **false**. An earlier "2 BigBots spawned" result was a
  **false positive**. Consequence: both files must live in `LJ/lua/maps/<MapName>/`.
- **`Import()` ignores a module's `return` entirely** — it captures only globals. A module written
  `local X = {} … return X` yields a table with none of its fields, silently, no error. Now law in
  `MODDING_SCRIPTING_SPEC.md`; the reason STEP70/72 test for `Scenario = {}` and forbid `local`.
- **The F1 in-game console is unreliable in this build** — showed nothing while confirmed-running
  code executed; `game_logs/*.txt` stayed empty. All live verification was done by spawning
  countable in-game objects as a visual signal channel.
- **`.sanmap` tolerates unrecognized top-level sections.** Live-verified by injecting a junk
  section into the real Pandemonium map and playing a 1v1. `LoadMapData` builds `GameInfo.MapData`
  from an explicit whitelist (`props, decals, areas, armies, markers, chains, groups`) and silently
  drops everything else. This is why `SANMAP_FORMAT_SPEC` Correction 17's `Scenarios` section is
  safe.
- **A window-close hang, unexplained.** A 543-line `.lua` in the map asset folder caused a
  force-quit-on-close; a 9-line stub did not. Mechanism unknown. No `.lua` lives there now.
